Medical College Manager — complete changelog.

= 1.32.0 =
* New: Gender field (Male / Female) for consultants and team members. It is
  never shown on the website and never sent through the REST API.
* New: Settings → Default Photo — Male and Default Photo — Female. A person
  without a photo now shows the photo for their gender, then the general
  Default Profile Image, then the built-in silhouette. People whose gender is
  not set look exactly as before.
* Default photos chosen from the Media Library are now served at the right
  size with srcset, width and height (faster, no layout shift).
* CSV import/export: gender column for consultants and team (Male, Female,
  M, F accepted, any case). An unrecognised value never skips the row: the row
  is imported with gender left blank (an update keeps the stored gender) and a
  warning is listed, e.g. "Row 12: gender 'Femal' not recognised – left blank".
  Import results now list warnings separately from skipped rows. Student gender
  values are normalised the same way (Male / Female / Other).
* Privacy: the personal-data exporter and eraser now include the gender of
  consultants and team members.
* Developers: mcm_default_avatar_url now also receives the post ID and gender.
* Display corrections (below) apply as soon as you update: they change how
  existing pages look, never what is stored. Tested: every post, field, term,
  department setting and plugin setting is identical before and after updating.
* Fixed: the table view of notices, tenders, scholarships, publications,
  research projects and policies showed only a Title column. Each now has its
  own columns (e.g. tenders: reference, category, closing date, department).
* Fixed: consultants and team members looked different depending on where
  they were shown. They now use the same profile card (photo, name, specialty,
  designation, department, one button) in shortcode grids, Elementor widgets,
  department pages and archives.
* Fixed: a person's page showed their photo as a full-width banner, or a
  full-width placeholder box when there was no photo. People now get a profile
  layout: the photo (or default photo) beside their details.
* Fixed: an odd number of details left an empty grey box on single pages; the
  last item now spans the full width. Featured images on single pages are at
  most 360 px high (220 px on phones) and timetable entries show no banner.
* Table titles now link to the entry's page (students stay plain text).
* Jobs: a new card in grid and directory views. Status and category on
  top, the department, posts / scale / type, the last date with the time
  left ("8 days left", "Closes today"; an extended date shows the old one
  struck through), the publication date and a View & Apply button aligned
  across the row. The whole card is clickable; the advertisement image is
  shown on the job's page instead of filling the grid.
* Directory filters (Jobs, Consultants, Team…): search field with an icon
  button, filter groups clearly separated, and long lists show the first
  six options with "Show all (n)" instead of a scrolling box (ticked options
  stay visible). On phones and tablets the filters fold behind a
  "Filters (n)" button so the results come first. Filter groups are
  labelled for screen readers and the heading order is correct.
* Admissions, scholarships, tenders and events show where they stand, in
  cards, list rows and on their own page: Upcoming / Open / Closing soon /
  Closed (events: Upcoming / Today / Past event) with the time left
  ("Opens in 5 days", "12 days left", "Tomorrow"), and a coloured top edge
  on cards.
* Cards: "View details" sits on the bottom edge of every card in a row.
* Notices: the priority is a badge; Urgent stands out in red.
* Fixed: on normal pages the theme underlined every link inside listings
  (titles, "View details", even white button text); single-page buttons
  were underlined too.
* Fixed: no space between the college header and the title of classic
  pages and posts.
* Accessibility: archive pages have a main landmark (the archive title no
  longer counts as a second site banner); correct heading order on single
  pages, archives and pages using the shortcodes; the photo link repeated
  next to each title is no longer a nameless tab stop; links in the hidden
  looping copy of the notice ticker and board are no longer focusable;
  larger filter checkboxes; the blog "Read More" link meets contrast.
* Tables: no stray gap under the table inside its frame. In timetable
  tables the Subject links to the entry's page (the timetable has no title
  column).
* Faster: the banner at the top of archive and department pages is no
  longer lazy-loaded (it is the largest image on screen; Lighthouse on a
  department page 72 → 88).
* The same link label in grid, list and directory views ("View details",
  "Meet the Consultant", "View Profile", "View & Apply" for jobs); developers
  can change it with the mcm_link_label filter.
* The default photos have their own "Default Photos" section in Settings.
* New: Staff Type for team members (Team → Staff Types). "Teaching & Technical
  Staff" and "Support Staff" are created once and can be renamed. Filter the
  Team list by staff type; staff_type="…" works in [mcm_team], the Team widget
  and the CSV import/export (staff_type column).
* New: College header & footer (College Manager → Header & Footer), off until
  switched on. Replaces the theme's header and footer on every page without
  editing the theme (Hello Elementor is switched through its own setting);
  if either part ever fails, the theme's own one is shown instead. Top bar
  with email, phone and a menu; logo and a main menu with dropdowns three
  levels deep (keyboard: arrows, Escape; the current department is
  highlighted); a mobile menu panel; static, sticky, smart-sticky or
  shrinking header; a four-column footer with the college logo, two link
  menus, contact details, the Social Bar icons, a copyright line and legal
  links; back-to-top. Five new menu locations (Appearance → Menus). All
  colours, sizes and texts are settings, with a warning when text would be
  hard to read; settings can be exported, imported and reset. Optionally
  uses your own Elementor templates instead of the built-in design. The
  Montserrat font is bundled (no Google request). Not shown on Elementor
  Canvas pages, chosen pages, or with block themes; steps aside where an
  Elementor Pro Theme Builder header/footer applies. Site Health reports
  anything that stops it from showing as set up.
  Also: separate logo heights for tablets and phones, an optional search
  button and call-to-action button (off by default), the top bar shown in
  full on phones if wanted, 4/3/2 footer columns, a "Reveal" footer style
  (off on short pages, small screens and for reduced motion), and a
  Typography tab (font, menu size and weight, footer heading size).
* Department pages: the hero image is now stored at full size and the HOD
  photo at large size when picked (sharp banners); existing pages unchanged.
* Accessibility: department and program pages no longer announce each section
  title twice to screen readers.
* PHP 8.5: CSV import no longer triggers a deprecation notice.
* Elementor widgets: every widget now has the full Elementor set of options.
  - Content: show Upcoming / Past events and Open / Closed admissions,
    scholarships and tenders; order by a field (e.g. event date, items
    without it last) or by the order items were picked; skip the first N;
    pagination; your own "nothing found" message.
  - Filters: search box, placeholder, which dropdowns and the Reset button
    can each be chosen; a starting search keyword (fixed when the search box
    is off); printed page heading.
  - Include / Exclude: leave out terms of any taxonomy; only these items or
    leave out these items. All of these survive live filtering and paging.
  - Style: cards, images, titles, details text, status badges, buttons, filter
    bar and fields, directory sidebar, table, citations, pagination, print
    button and the empty message, with Normal / Hover states where they
    apply. Existing pages look exactly as before.
  - Blog Posts: Grid layout with columns per device; show/hide image, date
    and read-more; exclude categories, tags, author, offset; full Style tab.
  - Notice Ticker / Board / List: "only from the last N days"; full Style tabs.
  The same options are available as shortcode attributes (see readme).
* Profile photos (consultants, team) are now square by default and sized by
  the card's width, so they keep their shape at 4, 5 or 6 columns instead of
  becoming tall strips; they are cropped toward the top, where faces are, and
  use a larger image file (medium_large) so they stay sharp. Display change,
  applies on update.
* Elementor listing widgets: Image proportions (square, portrait 4:5 / 3:4,
  tall 2:3, landscape 4:3 / 3:2, wide 16:9 or original, per device), crop
  focus, and Image quality (thumbnail … full size). Image height now also
  applies to profile photos.
* New Elementor widget: Contact Info — title, subtitle and rows of icon +
  label + value. Values can be clickable: phone (tel:), email (mailto:,
  encoded against harvesters), WhatsApp, Google Maps or a custom link, with an
  optional "number to use" when the shown text differs. Label left / value
  right or stacked, per device; per-row icon colour; full Style tab. A
  description list, so screen readers read each label with its value; links
  opening a new tab say so.
* Elementor listing widgets: new Display section. Photos: show (default photo
  when none uploaded, as before), only uploaded photos, or hide all photos
  (text-only cards) — for teams where only some staff have a photo. Show or
  hide specialty, designation, department, status badge, details, short
  description and the button. Table columns: pick which to show (e.g. a Team
  table without Staff Type and Specialty); with the name column hidden the
  first column links to the profile. The choices hold through live
  filtering, paging and printing. Same options as shortcode attributes
  (images, table_cols, show_*). Existing pages are unchanged.
* New Elementor widget: Testimonial / Message — heading (tag of your choice,
  across the full width or beside the photo), rich-text message, photo with
  image size, name, designation, organisation, optional profile link and
  quotation mark. Photo left, right or on top per device (default: right on
  desktop and tablet, top on phones). Full Style tab. Accessible: a labelled
  region, the message is a blockquote, the photo's alt text falls back to the
  name and a linked photo is not a second tab stop.
* Fixed: a paginated list on an ordinary page ([mcm_events paginate="yes"])
  showed page 1 again on /page/2/.
* Accessibility: the "Last date" label and old dates on job cards now meet
  4.5:1 contrast on the grey deadline box.
* Fixed: links in table view took the theme's hover colour (Hello Elementor);
  they now keep the plugin's link colour.

= 1.31.0 =
New: Jobs / Vacancies.
* New content type Jobs with Job Categories (Teaching Faculty, Clinical,
  Administrative, Support Staff are created once) and Departments. Fields:
  publication date, last date and closing time, extended last date, apply link
  and label, how to apply, job description and voucher/form (image or PDF),
  number of posts, scale, type, contact.
* Status is worked out from the dates in the site timezone: Open, Closing soon
  (Settings > "Closing soon" days, default 3), Extended (old date struck
  through), Closed. A job with a future publication date is hidden everywhere.
  Closed jobs leave the list but their pages stay online.
* [mcm_jobs] (alias [mcm_vacancies]) and an Elementor "Jobs / Vacancies" widget:
  status="open" (default), "closed" or "all", with category and department
  filters; the status survives search, filters, Reset and Print.
* Department pages get a Vacancies section while that department has open jobs.
* Notice board, ticker and list can show open jobs and open tenders next to
  notices (Settings > Notice board sources; per item "Show on notice board";
  include="notice,job,tender" per shortcode or widget).
* CSV import/export for jobs (sample-jobs.csv); tenders gain an on_board column.
* JobPosting structured data while a job is open; none once it closes.
* Vacancies print on the letterhead.
= 1.30.2 =
Reliability and hardening release. Nothing a visitor sees changes unless it was broken.
* Safety net: every module boots, and every shortcode, Elementor widget, archive
  page, single-page panel, JSON-LD block and live filter renders, behind its own
  error boundary. A failure shows visitors an empty block instead of a broken
  page, shows administrators a short notice, and is logged.
* New Tools > Site Health checks (PHP, WordPress, Elementor, recent errors,
  timezone, permalinks) and a Medical College Manager section in Site Health >
  Info. Errors are kept in a small log you can clear from there.
* Requirements gate: on WordPress older than 5.8 the plugin loads nothing but a
  notice. On Elementor older than 3.5 only the widgets are switched off (with a
  notice); shortcodes keep working.
* Fixed: pre-filters (department="", program="" … and Elementor pre-filter
  controls) were lost on the first search, filter change, Reset or Print. They
  are now always applied; with several terms visitors can narrow within them.
* Fixed: Upload / Select did nothing in post meta boxes and on the Add Department
  form. Fields can now accept images and PDFs.
* Fixed: CSV import merged rows that share a title (e.g. timetable slots). Rows
  now match by id only, unless you tick "Update existing entries with the same
  title"; rows of one file are never merged; the result names likely duplicates.
* Fixed: phone numbers such as +92-300… gained an apostrophe after export and
  re-import.
* Fixed: dates are validated and stored as YYYY-MM-DD (15/10/2026, 15-10-2026,
  15.10.2026 accepted; 31/02/2026 rejected) and times as HH:MM (2:30 PM accepted).
  An invalid value is not saved and the field is named in a notice or CSV error,
  so a tender can no longer vanish because of a mistyped deadline.
* Fixed: department pages showed an empty Tenders/Notices section when all of
  them had expired.
* Live filters now show "please refresh" when a request fails or the page has
  expired, work for content added later (Elementor editor, popups, tabs) and
  react to pasted text. New filter mcm_ajax_require_nonce for cached sites.
* New setting: Public student directory (Settings > Privacy), on by default.
  When off, the student list is shown only to staff who manage students.
* Privacy eraser: replaces the student's name, no longer skips records beyond
  20 per email, keeps the academic record, and reports accurately.
* Block themes (Twenty Twenty-Four/Five): archive and department pages now show
  the theme's header and footer. Elementor Pro Theme Builder archive templates
  take precedence when they match. Single-page details appear exactly once.
* Hello Elementor: plugin buttons and links keep their own colours on hover and
  focus.
* Stored values that are lists instead of text can no longer break a page.
* Clean-up: duplicate import keys and dead code removed; uninstall now removes
  every option, transient and capability on every site of a network.
* Fixed: after a live search or filter on a paginated list (archive pages, or a
  shortcode with paginate="yes"), the pager disappeared, so results beyond the
  first page could not be reached and Print printed only one page. The pager
  now stays and loads pages in place with the filters kept, and Print always
  prints the whole list.
* One-time upgrade: dates and times saved by older versions in another format
  (e.g. 15/10/2026, 2:30 PM) are converted to the standard format, so expiry
  and sorting work on them. Values that cannot be read are left unchanged and
  listed under Tools > Site Health > "Unreadable dates" with edit links. It
  runs in the background (first admin page or WP-Cron), never during a
  visitor's page load.
* If a part of the plugin is switched off after an error, its shortcodes show
  nothing to visitors instead of raw [shortcode] text.

Security hardening.

* [mcm_single] no longer renders non-public content (student records).

= 1.30.0 =
* Fixed: department / event videos set as a YouTube or Vimeo link now always
  display. The player is now built directly from the link instead of calling
  the provider over the network on every page load — which previously failed
  silently on many servers (Vimeo never worked, YouTube failed behind
  firewalls/proxies), leaving only the image. Every common link form is
  supported: youtube.com/watch, youtu.be, /embed/, /shorts/, /live/, and
  vimeo.com / player.vimeo.com. Pages also load faster (no outbound request).
* The hero banner (video or image) is now FULL-WIDTH and sits ABOVE the page
  title on department and listing pages, as a proper cinematic banner. Videos
  are centred at a sensible size; images span edge to edge. The full-width
  banner no longer introduces a stray horizontal scrollbar.
* The Head-of-Department card has been redesigned: a colour accent spine, a
  framed photo, and the email / phone now show as tidy pill buttons with
  icons — each appearing only when that detail is filled in.
* New per-department "Hide Sections" control: on a department, tick any
  sections you don't want on its page (e.g. hide the Timetable). Unticked
  sections still appear automatically whenever they have content.
* Security: unknown or internal URLs are still never embedded (SSRF-safe) and
  fall back to a plain link. Videos carry explicit dimensions so they never
  collapse to a tiny box when a theme's CSS is restrictive.
* Fixed: the archive / directory filter bar (search + dropdowns + Reset) now
  always stays on a single inline row. Some themes force every input and
  select to full width, which stacked the filters vertically; the bar now
  overrides that so it looks the same on every theme. Applies to the archive
  pages and the Elementor content widgets (they share the same filter bar).

= 1.29.0 =
* Events can now carry a live stream. Add a "Live Stream / Embed URL" to any
  event and the plugin shows the player at the top of the event page plus a
  "Watch Live" button in the details card. Left blank, nothing is shown - the
  feature is entirely optional and never displays an empty box. YouTube, Vimeo
  and direct MP4/WebM links are supported; unknown/internal hosts are never
  server-embedded (SSRF-safe) and fall back to a plain link.
* New "Page Banners" in Settings: give any public listing page (Events,
  Faculty, Scholarships, etc.) an optional hero video or image that appears
  above the list. Video takes priority over image; blank means no banner.
* Student lists ([mcm_students]) can be filtered by academic level, so
  graduate and undergraduate rosters can be shown separately. Only safe,
  public fields are ever rendered - no personal contact data is exposed.
* Research & Publication pages now label the lead as "Supervisor / Principal
  Investigator" and the team as "Assisting Students", matching institutional
  wording.
* Event live streams, department heroes and page banners now share one
  consistent, hardened media renderer.

= 1.26.0 =
Program is now the academic spine (architecture batch D).
* New shared "Program" connector taxonomy (MBBS/BDS/BSN…) on Courses,
  Timetable, Admissions and Students — the same pattern as Department and
  Faculty. A Program page now lists its own curriculum, schedule and intake,

= 1.25.0 =
CSV import is now an upsert — re-importing no longer creates duplicates.
* Export files include an "id" column; re-importing updates the exact record it
  came from instead of duplicating it.
* Hand-written CSVs (no id column) match an existing entry by its exact title
  within the type, so a corrected re-import updates rather than duplicates.
* Genuinely new rows still insert; the import summary now reports created,
  updated and skipped counts.
* Re-importing a file that omits the content/excerpt columns no longer wipes the
  existing body text — only columns present in the file are written.
= 1.24.0 =
Hardening, performance and accessibility pass (audit batch A).
* Performance: listing/table/directory renderers now read term names from the
  cache WordPress already primes instead of a fresh query per row — a 25-item
  directory dropped from ~59 queries to 14, and the print/export path no longer
  fires thousands of term queries.
* Security: the AJAX endpoint now serves only this plugin's own content types

* Accessibility: visible keyboard focus (:focus-visible) on all controls, an
  accessible label on the search box, scope="col" on table headers, alt text on
  card/list/single images, and a higher-contrast "New" badge.
* Fix: the responsive stacked-table layout no longer leaks into print, so the
  printed timetable and student list render as proper tables.

= 1.22.0 =
Student privacy — the public student list now shows safe fields only.
* The student list ([mcm_students]) shows only Name, Student ID, PMDC No.,
  Level, Program, Department, Batch and Status. The Contact (email) column has
  been removed.
* Email, phone, date of birth, home address, blood group, gender and guardian
  details are never rendered on the front end in any view — they remain in
  wp-admin for staff only.
* Whatever view is requested, students are forced to the safe table renderer,
  so a grid/card view cannot surface a student photo (the public list is names
  only) or any other field.
* Student search matches Name, Student ID, PMDC No., Program and Batch only —
  never email or phone, so the directory can't be used to confirm a student
  from their contact details.
* The public list can now be searched/filtered by anyone on those safe fields
  (previously student filtering was blocked for logged-out visitors). Sensitive
  data stays fully protected; only safe fields are ever returned.
* AJAX result counts are clamped (filter: mcm_ajax_max_count, default 1000) so a
  crafted request cannot ask for an unbounded list.

= 1.19.0 =
 * SECURITY: student records now have their own capabilities. Previously they
   used the default post capabilities, so every Author and Contributor could
   open the student roll and read PMDC numbers, emails, phones, dates of birth,
   addresses and guardian contacts. Access is now granted to Administrators
   only; use the mcm_student_roles filter to add a Registrar or Admissions
   role. All other content types are untouched - staff who manage timetables,
   events and faculty keep exactly the access they had.
 * Privacy: registered a personal-data exporter and eraser, so a subject-access
   or erasure request can be answered from Tools > Export/Erase Personal Data.
   Erasing anonymises the personal fields and keeps the academic record, since
   deleting enrolment history outright is rarely what a college wants.
