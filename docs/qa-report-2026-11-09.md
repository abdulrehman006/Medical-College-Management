## 1. What's working well

These parts were already solid before the audit. They are worth keeping as they are.

- **Failure isolation.** Every module boots behind its own error boundary. One broken module is switched off and reported in Site Health; the site keeps running. Render paths do the same, so a failing block shows administrators a short message and visitors nothing.
- **Data validation.** Dates and times are validated on every write path: meta box, CSV, REST, and other plugins calling `update_post_meta`. Invalid values are refused, never stored, and the editor is told which field to fix. Stored legacy values are flagged on the edit screen.
- **Privacy of student records.** Students are not public, not in REST, not in search, and have their own capability set (administrators only by default). Front-end student views render only safe columns, and the student search matches only safe identifiers.
- **Escaping, nonces and SQL.** The independent review traced every `phpcs:ignore` echo and found each one pre-escaped. Every form, import, export and settings handler checks a nonce and the right capability. Every `$wpdb` call is prepared. CSV export is protected against formula injection. The plugin registers no custom REST routes.
- **Expired content.**
  - Tenders and notices hide themselves after their deadline or expiry date.
  - Jobs close, and support extended deadlines and closing times.
  - Events show past or upcoming; admissions, scholarships and tenders show Open, Closing soon or Closed with days left.
- **Department pages.** They show only the sections that have content, in a sensible order. A department with nothing yet shows "There is nothing to show here yet." instead of empty sections.
- **Performance.** There are no N+1 queries: 2 or 20 items cost the same number of queries. Front-end CSS and JS load only on pages that use the plugin, and images use WordPress's srcset and lazy loading. The largest banner is deliberately loaded eagerly.
- **Accessibility.** axe-core found no serious or critical problems on any of the 56 pages. Each page has one H1 with no skipped heading levels, every image has alt text, filters have visible focus rings, and keyboard navigation works.
- **Cross-browser.** No issues in Chromium, Firefox or WebKit, from 320 to 1440 px.
- **Elementor is genuinely optional.** Without Elementor, every page, shortcode and admin screen works, including on WordPress 6.1 with PHP 7.4. Widgets load only after a version and class check.
- **Consistency.** Every Elementor widget, used with default settings, renders the same card or table as the plugin's own archive and department pages. Policies now match too (2.14).
- **Admin field set.** It is complete for a medical college: Vancouver citation fields with DOI, PMID and PDF for publications; principal investigator, status, dates, co-investigators and funding for research; OPD days and times for consultants; ORCID, Scholar and PubMed links for faculty; full job and tender fields.

## 2. Issues found

Each entry lists:
- **Area:** the content type or feature affected.
- **Persona:** who caught it: P1 admin, P2 visitor, P3 engineer (CR = the independent code review).
- **Severity.**
- **Description**, then **Steps / Expected vs actual**.
- **Fix** and **Status**.

All "Fixed" entries were re-verified behaviourally after the fix (section 0).

### 2.1 Public student roll reachable through the live-filter endpoint (High)
- **Area:** Students; AJAX filter.
- **Persona:** P3 (CR).
- **Description:** the public filter endpoint (`admin-ajax.php?action=mcm_filter`) accepted any `config` the browser sent. With "Public student directory" on, which is the default, anyone could request `type=mcm_student, count=1000`. That returned every student's name, Student ID, PMDC No., level, program, department, batch and status, even on sites that never place a student list on any page. Any other type, scope or sort could also be requested.
- **Steps:**
  1. Open any listing page.
  2. Read `MCM.nonce`.
  3. POST a config with `"type":"mcm_student","count":1000`.
- **Expected vs actual:** expected only the listing the page shows; actual was the whole roll.
- **Fix:**
  - The listing configuration is now signed on the server (HMAC with the site's salts, deterministic, so full-page caches still work).
  - The endpoint refuses any config whose type, pre-filters, sort, page size or display choices were changed.
  - Only the page number and Print all (up to 1000 items, and only for listings that have a Print button) may vary.
  - Shortcodes also refuse non-plugin types (2.4).
- **Status:** Fixed. Tampering with type, scope, page size, sort, print, display or ids is refused (403). Untouched configs, pagination and Print all still work.
- **Note:** whether the student directory should be public by default was a college decision (B-1). Decided 2026-11-09: **off by default**, now implemented (section 6.1).

### 2.2 No department-scoped permissions (High)
- **Area:** all content types; roles.
- **Persona:** P1.
- **Description:** any Editor could edit, publish or delete every department's content and every department page. There was no way to give a department's coordinator access to only their own department.
- **Steps:** log in as an Editor and open any department's course, consultant or department page. All of them were editable.
- **Fix:** new **Department access** setting (Users > Edit user, administrators only). A user with ticked departments:
  - sees only those departments' entries in the wp-admin lists;
  - can edit, delete or publish only those entries, plus their own new ones, which are put in their department automatically;
  - sees only their departments in the Departments box;
  - cannot add departments;
  - cannot remove a department they don't manage from a shared entry;
  - can edit only their own department pages.

  It is off unless departments are ticked, and administrators are never limited. A "Department access" column appears in the Users list.
- **Status:** Fixed. 23 permission checks and 8 browser checks pass, including a direct URL to another department's entry being refused (403).

### 2.3 Password-protected entries shown without the password (Medium)
- **Area:** all types; `[mcm_single]`, listings, notice board, JSON-LD, department sections.
- **Persona:** P3 (CR). The notice-board and department-section cases were found while verifying the fix.
- **Description:** `[mcm_single id="…"]` printed the full body and attachment of a protected entry. Cards and tables printed its fields. The notice board and ticker listed protected notices with their attachment link. Structured data printed email and phone. Department pages counted protected entries and could show an empty section.
- **Fix:**
  - Protected entries are left out of listings, the notice feed and department-section counts.
  - `[mcm_single]` and JSON-LD skip them.
  - The entry's own page still shows WordPress's password form.
- **Status:** Fixed and verified (protected entry absent from `[mcm_single]`, `[mcm_notices]`, the board, the ticker and the generic listing).

### 2.4 Shortcodes listed any post type (Medium)
- **Area:** `[mcm_grid]`, `[mcm_list]` and `[mcm_table]`.
- **Persona:** P3 (CR).
- **Description:** `type="…"` was passed straight to WP_Query. An Author could list another plugin's published-but-private records, such as form submissions, on a page.
- **Fix:** only this plugin's types, and only those the viewer may list.
- **Status:** Fixed; `type="post"` and an unknown type both render nothing.

### 2.5 The public endpoint was expensive to call (Medium)
- **Area:** AJAX filter; search.
- **Persona:** P3 (CR).
- **Description:** anyone could ask for 1000 items, random order, and a member search that joined every meta row of every post before matching with `LIKE`. A simple loop could load the database on shared hosting.
- **Fix:**
  - Page size and sort are now fixed by the signed config (2.1).
  - The member search joins only the searchable fields.
- **Status:** Fixed. Search still finds team members by designation and students by Student ID, and never by private email.

### 2.6 Filter and count caches did not persist between requests (Medium)
- **Area:** filters on every listing; admin counts.
- **Persona:** P3 (CR).
- **Description:** the caches used `wp_cache_*`, keyed on WordPress's "last changed" stamps. Without a persistent object cache, which is typical shared hosting, both the cache and the stamps reset on every request. The work was redone on every page view: up to a 2000-ID query per filter group.
- **Fix:**
  - Transients keyed on a stored "listing version", which changes whenever plugin content, its fields or its terms change.
  - Several changes in one request (bulk edit, import) move the version in memory at once and store it once at the end.
  - A first version cached under the old key during a bulk change; the re-run caught this and it was fixed before commit.
- **Status:** Fixed. Counts update straight after add, draft and delete (the taxonomy suite passes).

### 2.7 Missing departments, programs and dates were not flagged (Medium)
- **Area:** Team, Consultants, Courses, Timetable, Publications, Research, Events, Tenders, Scholarships, Admissions.
- **Persona:** P1.
- **Description:** only the title was required. A team member published with no department never appeared on any department page or filter, and nothing said so. The same applied to a course with no program, or a tender with no deadline (which then never closes).
- **Steps:** publish a Team Member with only a title.
- **Expected vs actual:** expected a warning; actual was the normal "Post published." message only. (Jobs already warned about a missing last date.)
- **Fix:**
  - After saving, a warning such as "This Team Member is published, but it has no Department…".
  - A "Missing: Department" label next to the title in the list.
  - A "Needs attention (n)" view listing every flagged entry of that type.
  - Publishing is not blocked.
- **Status:** Fixed. Whether publishing should be blocked instead was B-2. Decided 2026-11-09: **keep the non-blocking warning** (section 6.3).

### 2.8 Expired or closed status not visible in admin lists (Medium)
- **Area:** Tenders, Scholarships, Notices (also Admissions and Events).
- **Persona:** P1.
- **Description:** the front end hides or labels expired content correctly, but the admin lists showed no deadline or status. An editor could not see which tenders or notices visitors could actually see.
- **Fix:** a "Status on website" column showing, for example, "Open / 24 Nov 2026", "Closed — hidden", "Expired — hidden" or "No deadline — stays open".
- **Status:** Fixed.

### 2.9 Notice attachment and tender document were paste-a-URL only (Medium)
- **Area:** Notices, Tenders.
- **Persona:** P1.
- **Description:** the fields were plain URL boxes, so staff had to upload a file in Media and copy its link. Jobs, Publications, Research and Policies already had an upload button.
- **Fix:** Upload / Select buttons using the Media Library. Notices accept PDF, images and Word; tenders accept PDF, Word and ZIP. Pasting a URL still works.
- **Status:** Fixed (the button opens the Media Library).

### 2.10 Scholarships had no place for documents (Medium)
- **Area:** Scholarships.
- **Persona:** P1.
- **Description:** there was no field for an application form or guidelines.
- **Fix:** a new "Documents: form / guidelines" field with an upload button. It is shown as a download button on the scholarship page and can be imported by CSV (`scholarship_doc`).
- **Status:** Fixed.

### 2.11 Single pages had no cross-links (Medium)
- **Area:** every single page; Team and Consultants.
- **Persona:** P2.
- **Description:**
  - Department, Faculty, Specialty, Session and category values printed as plain text, so a visitor on an event could not reach its department.

- **Fix:**
  - Every taxonomy value in the details panel links to its page.
  - Team and consultant profiles list the person's publications and research projects, linked through their Faculty term, with an "Everything by …" link when there are more.

### 2.12 No meta descriptions (Medium)
- **Area:** all plugin pages (SEO).

  - archive, department and faculty pages get a short line.

  It is limited to 160 characters and can be changed with the `mcm_meta_description` filter.
- **Status:** Fixed (the sweep finds 0 pages without one).

## 6. Round 2: the college's decisions (2026-11-09)

### 6.1 Student directory: off by default (B-1, resolved)
- **Change:**
  - The setting's default is now OFF.
  - Because the site has not launched, the stored value is also switched off once, on the first page load after the update (flag option `mcm_students_default_off`).
  - After that the plugin never touches the setting again, so an administrator who turns it on keeps that choice.
- **Settings copy:** the setting now reads "Make student lists public (opt-in, off by default)". It states that, when on, every student list on the site shows each student's Name, Student ID, PMDC No., Level, Program, Department, Batch and Status to any visitor, searchable by Student ID or PMDC No. It also states that contact, date of birth, address, blood group, gender and guardian details are never shown. There is a matching readme FAQ entry.
- **Verified in the browser:**
  - Box unticked after the update.
  - OFF: the student page shows nothing to visitors.
  - Admin turns it ON in the real settings screen: the visitor sees the table and the live search by Student ID works.
  - ON: the page's own signed config is served. Raising the page size, asking for private columns and an unsigned request are all refused (403).
  - Turned OFF again: the previously valid signed config is refused too.
  - The signed-listing protection (2.1) applies unchanged when the directory is on.

### 6.2 "Sort by" control (B-3, new feature, not a bug fix)
- **What:** a "Sort by" dropdown with **Newest first** (default) and **Alphabetical (A–Z)**.
- **Where:** on every archive page, every listing with a filter bar or directory sidebar, and department-page sections that have filters.
- **Elementor:** every listing widget has a new **Sort control** switch (Filters & Tools, on by default). This covers Team, Consultants, Publications, Research, Events, Tenders, Scholarships, Vacancies (Jobs), Courses, Programs, Policies, Admissions and Timetable.
- **Notices:** the notices archive and filterable notice listings have the control. The three Notice feed widgets (ticker, board, list) have no filter bar and a fixed pinned-first order, so they are unchanged.
- **Combines with filters:** sorting changes only the order. The visitor's department / session / specialty / faculty selections, the search box, the author's pre-filters and status (open / closed / upcoming) all stay. The choice also carries through the pager and Print all.
- **Archive and widget behave identically:** both use the same renderer and the same signed config. The sort value is the only field a visitor may change, and it is validated to `newest` or `az`.
- **Meaning of "Newest first":** for publications, newest publication year; for everything else, newest publish date.
  - **Behaviour change to note:** vacancy listings that show the control now start with the newest posted job instead of the closing-soonest job. Listings without a filter bar (for example a plain jobs grid, or a small department section) keep the closing-soonest order.
- **Author's own order:** if an author set an order (Elementor "Order by", or a shortcode `orderby`), the control adds a **Default order** choice and starts on it, so the label always describes what is shown. `orderby="title" order="ASC"` starts on A–Z.
- **Shortcodes:** `sort_control="no"` hides the control; `sort="az"` starts alphabetical.
- **Verified:**
  - PHP, 28/28: every one of 13 types sorts correctly both ways with the same items, also combined with a filter.
  - Browser, 85/85 in each of Chromium, Firefox and WebKit, on 16 pages:
    1. the control starts on Newest first;
    2. filter, then A–Z: the same filtered items, alphabetical, filter still applied;
    3. back to Newest: the original order returns;
    4. search plus sort;
    5. the pager continues alphabetically;
    6. Print all sends the sort;
    7. at 375 px the control is reachable without horizontal scrolling.
  - The Elementor editor switch removes the control in the live preview.
- **Found and fixed while testing:**
  - The job card's closing time had 4.42:1 contrast on its grey box; it is now 4.5:1 or better.
  - Version-stale cache rows piled up in the options table (766 after a day of heavy testing). They are now deleted at the end of the request that made them stale.

### 6.3 Missing department: non-blocking warning (B-2, confirmed, deliberate)
No code change, by decision.
- Entries without a department (or program or key date) can still be published.
- The editor gets a warning after saving, a "Missing: …" label and the "Needs attention" view (2.7).
- **Reasoning:** blocking would stop CSV imports half-way and would stop college-wide entries (college notices, tenders, events) that legitimately have no department.
- This is a deliberate choice, not an oversight.
